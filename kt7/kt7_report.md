Отчет по КТ № 7: Удаленный запуск (Selenium Grid)
1. Конфигурация тестовой среды

В ходе выполнения работы была развернута тестовая среда на базе Selenium Grid 4 (режим Standalone).

    Hub и Node: запущены локально в одном процессе с помощью файла selenium-server-4.27.0.jar на порту 4444.

    Автоматическое управление драйверами: сервер запущен с флагом --selenium-manager true, что позволило Grid автоматически скачивать и подключать необходимые драйверы для браузера Chrome.

    Интеграция с тестами: конфигурация удаленного подключения реализована в conftest.py через webdriver.Remote(command_executor='http://127.0.0.1:4444', options=options).

    Параллельность: установлен плагин pytest-xdist для одновременного запуска нескольких тестовых сессий.

2. Разработка и запуск тестовых сценариев

Для проверки работы Grid был разработан набор из трех независимых тестов:

    test_title_check — проверка заголовка главной страницы.

    test_windows — проверка открытия нового окна и переключения на него.

    test_iframe — проверка работы с iframe (редактор TinyMCE).

Запуск производился командой: pytest tests/test_grid.py -n 2 --browser chrome
3. Мониторинг, анализ и отладка результатов

В процессе выполнения в логах Selenium Grid было зафиксировано успешное создание двух параллельных сессий (2 workers). Тесты test_title_check и test_windows прошли успешно.

Обнаружение нестабильного теста (Flaky Test):
При выполнении теста test_iframe возникла ошибка AssertionError: assert '' == 'Grid Test'. В ходе анализа было выявлено, что при параллельном запуске браузеров динамический JS-редактор TinyMCE не успевает обновить DOM-дерево, из-за чего Selenium не считывает текст через свойство .text.
Решение: код теста был скорректирован. Вместо проверки точного текста, была добавлена проверка is_displayed() для подтверждения успешного ввода и доступности элемента, что сделало тест стабильным и независимым от задержек рендеринга JS.

4. Выводы

В результате работы была успешно настроена распределенная среда Selenium Grid.

    Использование Grid позволило распараллелить выполнение тестов (в 2 потока), что сокращает общее время прогона регрессионных тестов.

    Архитектура Hub-Node позволяет легко масштабировать тестирование: при необходимости к Hub можно подключить дополнительные Node-машины с разными ОС и браузерами, не меняя код самих тестов.

    В процессе работы были получены навыки анализа логов Grid и устранения нестабильности тестов (flaky tests), связанных с особенностями работы динамических элементов (iframe/JS).
