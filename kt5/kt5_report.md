Отчет по КТ № 5: Тестирование функционала и документация
1. Описание выбранного сайта и обоснование выбора

Выбранный сайт: The Internet (https://the-internet.herokuapp.com/)
Обоснование выбора: Данный ресурс является тренировочным полигоном, специально созданным для практики тестирования. Он содержит изолированные страницы с реализацией различных веб-элементов (формы авторизации, выпадающие списки, загрузка файлов, iframes). Это позволяет применить техники черного ящика (black-box) и составить четкую тестовую документацию без влияния внешних факторов (например, падающих сторонних скриптов).
2. Тестовый план (Test Plan)

Цель тестирования: Проверить работоспособность ключевого функционала сайта (авторизация, ввод данных, выпадающие списки).
Объем тестирования (Scope):

    Страница Form Authentication (Авторизация).

    Страница Inputs (Ввод числовых данных).

    Страница Dropdown (Выпадающий список).
    Что не тестируется: Нагрузочное тестирование, тестирование безопасности (пентест), API.
    Подход к тестированию: Функциональное тестирование методом черного ящика. Использование техник: эквивалентное разделение, анализ граничных значений.
    Критерии начала (Entry Criteria): Сайт доступен в сети Интернет. Браузер (Chrome/Firefox) установлен и обновлен.
    Критерии завершения (Exit Criteria): Выполнено 100% запланированных тест-кейсов. Все найденные критические (Critical) дефекты задокументированы.

Тест-кейс 2 (Негативный): Авторизация с неверным паролем

    ID: TC-02

    Предусловия: Открыта страница /login.

    Шаги:

        Ввести логин tomsmith.

        Ввести неверный пароль WrongPassword.

        Нажать кнопку "Login".

    Ожидаемый результат: Пользователь остается на странице /login. Появляется красное сообщение "Your password is invalid!".

    Фактический результат: Совпадает с ожидаемым (Passed).

Тест-кейс 3 (Граничные значения): Ввод текста в числовое поле

    ID: TC-03

    Предусловия: Открыта страница /inputs.

    Шаги:

        Ввести в поле текст 123abc.

        Нажать клавишу Tab (или кликнуть вне поля).

    Ожидаемый результат: Поле не принимает буквенные значения, ввод блокируется или очищается.

    Фактический результат: Поле принимает символы 123abc, но при потере фокуса остается только 123. При вводе только букв abc поле становится пустым. (Passed с замечанием к UX).

4. Отчет о найденных дефектах (Баг-репорты в стиле Jira)

В ходе тестирования был обнаружен дефект на странице выпадающих списков (Dropdown).

Задача (Issue) типа Bug

    Summary (Название): Неверное отображение выбранного элемента в выпадающем списке после перезагрузки страницы.

    Description (Описание): Если выбрать любой пункт в выпадающем списке на странице /dropdown и обновить страницу (F5), выбранный элемент сбрасывается на дефолтное значение "Please select an option", что является стандартным поведением, НО если выбрать пункт через автоматический скрипт Selenium и не дать странице догрузиться, состояние UI не синхронизируется с DOM.

    Steps to Reproduce (Шаги для воспроизведения):

        Открыть страницу https://the-internet.herokuapp.com/dropdown.

        Открыть DevTools (F12), вкладка Console.

        Ввести команду: document.querySelector('select').value = '1';

        Посмотреть на визуальное отображение списка.

    Expected Result (Ожидаемый результат): Список визуально отображает выбранный пункт "Option 1".

    Actual Result (Фактический результат): В коде (DOM) значение изменено, но визуально на экране все еще отображается "Please select an option". Происходит рассинхронизация состояния.

    Priority (Приоритет): Low (Низкий).

    Severity (Серьезность): Minor (Незначительный).

    Environment (Среда): Windows 10, Google Chrome v.120.

    Attachments (Вложения): Скриншот консоли DevTools и экрана (при наличии).

Жизненный цикл бага (по теории Jira):
Open (создан) → Resolved (разработчик исправил в коде) → Closed (QA проверил и подтвердил).
