Отчет по КТ № 11: Robot Framework и ATDD/BDD
1. Цель работы

Изучить возможности фреймворка Robot Framework для автоматизации тестирования и применить на практике подходы ATDD (Acceptance Test-Driven Development) и BDD (Behavior-Driven Development) при написании тестовых сценариев.
2. Инструменты и тестовое окружение

    Фреймворк: Robot Framework.

    Библиотеки: SeleniumLibrary (для взаимодействия с веб-элементами), robotframework-seleniumlibrary.

    Язык написания тестов: Gherkin-подобный синтаксис (Given / When / Then).

    Браузеры: Google Chrome, Mozilla Firefox (проверена кроссбраузерность).

3. Архитектура проекта (Модульность)

В соответствии с лучшими практиками, проект разделен на слои, чтобы избежать дублирования кода:

    variables.py — хранит тестовые данные (URL, логин, пароль, название браузера). Благодаря этому для смены браузера с Chrome на Firefox достаточно изменить одну строку.

    resources/keywords.robot — содержит реализацию ключевых слов (Low-level actions). Здесь прописаны конкретные селекторы и команды Selenium (например, Input Text id=user-name ${VALID_USER}).

    tests/test_cases.robot — содержит сами тестовые сценарии (High-level scenarios), написанные на понятном бизнес-языке (BDD).

4. Реализация BDD-подхода (10 тестовых сценариев)

Были разработаны 10 тестов, покрывающих ключевой функционал сайтов SauceDemo и The Internet Herokuapp.
Тесты написаны по шаблону Given-When-Then (Дано-Когда-Тогда), что позволяет читать их даже людям без технического бэкграунда:

    TC01: Успешная авторизация (Позитивный).

    TC02: Авторизация с неверным паролем (Негативный).

    TC03: Добавление товара в корзину.

    TC04: Проверка сортировки товаров по цене (от низкой к высокой).

    TC05: Проверка работы чекбоксов.

    TC06: Проверка работы выпадающего списка (Dropdown).

    TC07: Проверка заголовка главной страницы.

    TC08: Проверка наличия формы логина.

    TC09: Проверка выхода из системы (Logout).

    TC10: Проверка переключения на iframe и ввода текста в WYSIWYG-редактор.

5. Анализ результатов и отладка

В ходе выполнения работы тесты запускались командой robot --outputdir reports tests.
Изначально возникали сложности с нестабильными элементами (Flaky tests), которые были успешно устранены:

    Проблема с iframe (TC10): Текст не вводился, пока не был добавлен явный клик по редактору перед вводом.

    Проблема с Logout (TC09): Ожидание index.html в URL не срабатывало, так как сайт перенаправляет на корень домена. Ожидание было заменено на проверку появления поля логина.

    Проблема с соцсетями: Элементы в футере оказались скрытыми; их проверка была заменена на проверку наличия в DOM-дереве.

Итоговый статус: Все 10 тестов успешно пройдены (PASSED) в браузере Firefox и Chrome.
Сгенерирован подробный HTML-отчет (report.html), содержащий логи каждого шага, время выполнения и статистику.
6. Выводы

Robot Framework отлично подходит для реализации подходов ATDD/BDD.
Использование Gherkin-синтаксиса и вынесение логики в отдельные ключевые слова (Keywords) делает тесты:

    Читаемыми (понятными для заказчика и бизнеса).

    Масштабируемыми (легко добавлять новые шаги).

    Поддерживаемыми (при изменении верстки правится только одно ключевое слово, а не 10 тестов).
    Автоматизация с помощью Robot Framework доказала свою эффективность для регрессионного тестирования веб-приложений.
